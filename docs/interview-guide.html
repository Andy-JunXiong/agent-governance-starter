Thirty-second positioning

Agent Governance is a repository-native control layer for AI-assisted software development. It connects human-owned task intent to architecture context, bounded file scope, fresh validation evidence, and explicit review. Deterministic checks report facts; people retain semantic and consequential authority.

Release boundary: stable 0.2.1 provides the installable repository-governance CLI. Published prerelease 0.3.0rc1 and newer development source extend that foundation into coding-agent lifecycle governance.

The interview story

  1. Problem: AI coding is fast while task ownership, scope, evidence, and authority can remain implicit.
  2. Architecture: repository files own truth, a dependency-free Python CLI checks facts, host adapters mediate interaction, and humans retain judgment.
  3. Visible demo: filter the illustrative 0.3.0rc1 sample report by PASS, WARN, FAIL, and ADVISORY.
  4. Current evidence: trace one admitted task through alignment, scope, validation, self-review, status, and pause in the evidence portfolio.
  5. Latest safety slice: explain immutable reservation, create-only claim, and separate immutable recovery evidence.
  6. Close honestly: identify what remains unknown and what still requires a human decision.

Latest development-source evidence chain

  1. Reserve: create one immutable correlation reservation under exact human confirmation.
  2. Claim: exclusively create one durable pre-run owner claim without mutating the reservation.
  3. Recover: inspect exact bounded claim bytes and separately record immutable supersession evidence.
  4. Remain bounded: recovery preserves the original claim, creates no replacement owner, and grants no replay authority.

Likely questions

Why is this not just another linter?

It binds the human-owned task, architecture context, path scope, validation snapshot, advisory review, and authority boundary while refusing to infer semantic correctness from static checks.

Why no governance score?

A score would hide the difference between a satisfied contract, honest incompleteness, a deterministic failure, and a judgment only a person can make.

What comes next?

Not yet decided or authorized. The strongest candidate is a recovered-correlation re-ownership contract before any claim-to-Harness consume transition.

Honest limitations

  • Static checks cannot prove requirement value, architecture quality, reviewer comprehension, or test sufficiency.
  • The sample report is a sanitized illustrative snapshot, not proof of the newest development workflow.
  • Recovery does not authenticate the individual operator or authorize replay.
  • Network-filesystem exclusivity, power-loss durability, and real-consumer recovery remain unvalidated.
  • No external evidence proves that this documentation improves interview outcomes.
