30 秒定位

Agent Governance 是面向 AI 辅助开发的仓库原生控制层。它把人工拥有的任务意图、架构上下文、允许修改的文件范围、新鲜验证证据和明确复核连接起来。确定性检查只报告事实；语义判断和高后果权限继续由人掌握。

版本边界：稳定版 0.2.1 提供可安装的仓库治理 CLI；公开预发行版 0.3.0rc1 与更新开发源继续扩展 Coding Agent 生命周期治理。

面试故事线

  1. 问题：AI 写代码很快，但需求归属、范围、证据和权限经常仍是隐含的。
  2. 架构：仓库文件拥有事实，无依赖 Python CLI 检查契约，宿主 Adapter 协调交互，人保留判断。
  3. 可视化：打开经过清洗的 0.3.0rc1 示例报告，筛选 PASS、WARN、FAIL、ADVISORY。
  4. 当前证据：在证据作品集中追踪任务的对齐、范围、验证、自审、状态和暂停。
  5. 最新安全切片：解释不可变 reservation、create-only claim 和单独的 immutable recovery evidence。
  6. 诚实收尾：说明仍未知的事实和必须由人决定的事项。

最新开发源证据链

  1. Reserve：在精确人工确认下创建一个不可变 correlation reservation。
  2. Claim：独占创建一个持久的运行前 owner claim，不修改 reservation。
  3. Recover：只读检查有界的精确 claim bytes，并单独记录不可变 supersession evidence。
  4. 继续受限：恢复保留原 claim，不创建 replacement owner，也不授予 replay 权限。

常见面试问题

为什么不只是另一个 linter？

它同时绑定人工拥有的任务、架构上下文、路径范围、验证快照、建议性复核和权限边界，并拒绝从静态检查推断语义正确性。

为什么不做治理评分？

单一分数会掩盖“契约满足、诚实不完整、确定性失败、只能由人判断”之间的差别。

下一步做什么？

尚未决定或授权。最强候选是在 claim-to-Harness consume 之前定义 recovered-correlation re-ownership 契约。

主动说明的限制

  • 静态检查不能证明需求价值、架构质量、审阅者理解程度或测试充分性。
  • 示例报告是清洗后的说明性快照，不是最新开发工作流的证明。
  • Recovery 不认证具体操作者，也不授权 replay。
  • 网络文件系统独占语义、断电耐久性和真实消费者恢复仍未验证。
  • 没有外部证据证明这些文档能改善面试结果。
