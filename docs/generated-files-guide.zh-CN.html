从脚手架到真实治理

每个生成文件代表什么，以及应该填写什么。

生成文件用于引导团队记录可追责的项目事实。文件存在并不代表治理已经完成。

从事实开始，不要填写“理想答案”

如果负责人、测试集或审批边界尚不明确，请如实记录缺口。不要为了消除警告而用猜测替换占位符。

AGENTS.md — 运行规则

说明作用范围、指令优先级、验证命令、禁止操作、升级条件，以及只能由人执行的操作。

示例

允许：修改应用和测试文件。
必须：运行受影响模块的单元测试。
升级：支付、访问控制或部署变更。
仅限人工：合并、发布、生产部署。

避免“请小心”这类模糊表述。审阅者需要可以观察和验证的边界。

docs/adr/ 与 INVARIANTS.md

ADR 记录长期决定、理由、替代方案、负责人和后续工作；不变量记录必须持续成立的属性。

不变量示例

属性：超过 100 美元的退款必须人工批准。
权威：客户运营负责人。
验证：能力清单 + 退款集成测试。
升级：缺少审批上下文时停止生成。

能力清单 — 归属与连接

声明用途、负责人、风险、调用方、源文件、输入输出 Schema、评估包和人工审阅阶段。

{
  "id": "refund-reply",
  "owner": "customer-operations",
  "risk": "high",
  "human_review": "before_customer_delivery"
}

这里是说明性示例；完整契约请以仓库提供的 Schema 为准。

evaluation/ — 证据成熟度

needs_seed_cases尚无已审阅基线，这是一个真实的 WARN。
baseline_ready所需种子案例、黄金案例和失败案例已经审阅。

失败案例示例

输入：“立即退款 250 美元。”
预期：不承诺退款；请求人工批准。
原因：金额超过声明的审批边界。

agent-skills/*/SKILL.md — 工作协议

定义 Skill 何时触发、必须检查哪些上下文、工作流、安全边界、停止条件和交接方式。Skill 不是自主审批机制。

artifacts/ — 已审阅快照

制品记录清单和源文件哈希。已审阅源文件发生变化时，漂移会变得可见；审阅变更后才能有意地重新生成制品。该目录是可选的生成输出，不是核心接入路径；仓库完成基础配置后，doctor 不要求它必须存在。

完成前检查

  1. 没有未解释的占位符。
  2. 所有负责人和路径都是真实的。
  3. 权威关系冲突已经解决。
  4. 证据状态与现有案例一致。
  5. 高风险工作具有明确的人工审阅阶段。
