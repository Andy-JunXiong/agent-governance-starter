# Agent Governance Starter Kit Development Log — 2026-08-01

## Outcome

AgentGov now has a bounded consumer-CI integration path and a visible repository
status surface. The NYC Taxi repository is connected as the first pilot without
copying project runtime code into AgentGov or granting automation authority to
merge, release, or deploy.

The local release candidate is now identified honestly as `0.2.0rc1`, while
the NYC consumer workflow remains pinned to the published stable `0.1.0`
release.

## Work completed

- Added `agentgov integrate github-actions` with:
  - create-missing-only behavior;
  - explicit `CREATE`, `PRESERVE`, and `CONFLICT` planning;
  - exact interactive `INTEGRATE` confirmation;
  - redirected and non-interactive write denial;
  - revalidation and exclusive creation before writes.
- Added a pinned GitHub Actions workflow that:
  - installs the published AgentGov 0.1.0 wheel independently from project
    dependencies;
  - runs repository validation on pushes and pull requests;
  - writes a Markdown report to the GitHub job summary;
  - uploads JSON, Markdown, and update-state artifacts;
  - preserves read-only permissions and human authority boundaries.
- Added `agentgov status` with text and strict JSON output for adoption, layout,
  CI state, capabilities, active governance surfaces, finding totals, and the
  next selected action.
- Added deterministic Markdown status output for GitHub job summaries. Future
  0.2-or-newer managed workflows append and upload this status card while the
  byte-exact stable 0.1 NYC workflow remains unchanged.
- Corrected next-action scoping so only capability evaluation findings produce
  capability-scoped evaluation commands.
- Recorded the NYC source boundary and reuse decision before adapting the
  consumer integration pattern.
- Created the bounded workflow in NYC and documented where governance runs,
  what reviewers see, and what AgentGov does not authorize.
- Added SHA-256 verification before the consumer workflow installs the pinned
  stable wheel.
- Added ADR-0007 and `agentgov plan upgrade-pr` as the read-only contract for a
  future automatic upgrade PR writer. The planner blocks custom workflows,
  incompatible versions or layouts, and releases that declare migrations.
- Added `agentgov benefits compare` to compare two repository-report snapshots
  with exact denominators and without causal, prevented-incident, coverage, or
  ROI claims.
- Added a `benefit_evidence` status surface that distinguishes CI repositories
  ready to collect comparable reports from repositories without that surface.
- Generalized exact managed-workflow recognition across pinned release versions
  so a future AgentGov update remains eligible for the following update.
- Hardened benefit comparisons by recalculating each report summary from its
  findings and rejecting altered or internally inconsistent counts.
- Prepared local release candidate 0.2.0rc1 with release notes, aligned runtime
  and manifest versions, and stricter release-manifest generation. The builder
  now declares stable 0.1.0 as the supported source and rejects mismatched
  channel, version, or wheel filenames.
