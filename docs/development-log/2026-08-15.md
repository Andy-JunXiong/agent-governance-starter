## Safe Documentation Index Writer v1

### Goal, alignment, admission, and boundaries

After reviewing the compact candidate, the product owner confirmed that the
directory index is needed and selected an explicit safe writer through a new
native alignment journey. Native proposal review admitted the exact low-risk
task `p0-safe-documentation-index-writer-v1`, and the product owner took it up
in a separate instruction.

The slice may create or update only `docs/development-log/INDEX.md`. Every
dated log remains at its stable path and must stay byte-identical during an
apply. Automatic closeout refresh, scheduling, reminders, source-log writes,
schema-shape changes, Git, publication, release, deployment, and external
actions remain excluded.

### Implementation

- `agentgov plan documentation-archive ... --apply` keeps ordinary planning
  read-only, rejects JSON/apply combinations, and requires a real interactive
  terminal plus the exact phrase `APPLY INDEX` before a create or update.
- Apply regenerates and compares the complete immutable plan, including the
  through-date, ordered entry metadata and source hashes, findings, action,
  candidate content, and target before/after digests.
- An absent index uses exclusive creation. An update writes and flushes a
  same-directory temporary file, revalidates again, preserves target mode, and
  uses `os.replace`; the temporary path is removed after success or failure.
- No-op plans return without prompting or writing. Failed, unsafe, stale,
  non-interactive, declined, mismatched, and interrupted paths remain bounded.
- The strict `agentgov.documentation-archive-plan` 1.0 JSON shape remains
  unchanged and continues to deny apply authority; the explicit CLI action is
  a separate human-confirmed boundary.
