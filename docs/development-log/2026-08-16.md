## Clean-target replay preflight

The product owner reviewed three directions and selected a dedicated
read-only replay-preflight contract, evaluator, and CLI instead of extending
`doctor` or admitted-task scope. Native task proposal review admitted
`p0-clean-target-replay-preflight-v1` for the exact starter-repository slice.
No consumer cleanup, mutation, replay, Adapter installation, Git operation,
publication, release, or deployment was admitted.

Development source now provides `agentgov.replay-preflight-plan` version `1.0`,
its strict JSON Schema, a dependency-free evaluator, and
`agentgov check replay-preflight`. The evaluator binds an expected Git
revision, exact target paths and explicit byte or text preconditions, exact
related-task absence, strict local Adapter identity and protocol metadata, and
one `rpf-` correlation marker lookup. It reports `READY`, `BLOCKED`, or
`UNKNOWN`; every non-ready result blocks replay consumption, while every
result retains an all-false cleanup, replay, task, Git, release, deployment,
and publication authority boundary. `READY` proves only the named
prerequisites.

The implementation uses read-only Git commands, includes both rename
endpoints and untracked paths, rejects duplicate JSON keys and unsafe paths,
and treats symbolic links, missing Git facts, and untrustworthy Adapter
metadata as `UNKNOWN`. Correlation lookup is intentionally read-only: it does
not create or reserve a marker and cannot eliminate a time-of-check and
time-of-use race. Existing `doctor`, admitted-task scope, Harness, Adapter, and
governance MCP meanings remain unchanged.
