## Harness Contract v1 implementation

After reviewing the completed baseline, the human product owner selected the
offline Harness Contract v1 route over immediate form-layer diagnosis or a
pause. Native alignment recorded that choice. The separately presented task
proposal was admitted through the human form, validated, and then taken up in a
distinct human instruction.

The bounded implementation adds:

- strict `agentgov.harness-run` 1.0 schema and matching dependency-free Python
  validation;
- deterministic ordered comparison of expected and observed transition facts;
- three separate Agent-selection, AgentGov-decision, and intervention-outcome
  channels;
- exact First Deviation verification;
- honest host capability and `OBSERVE` / `ADVISE` / `MEDIATE` / `BLOCK` result
  boundaries;
- sanitized matching and AIRBNB fixtures; and
- negative conformance cases for privacy, path, ordering, duplication,
  enforcement, post-action honesty, terminal facts, claims, and authority.

The AIRBNB fixture derives proposal materialization as the first deviation and
retains the later form-mediation absence without reassigning it as the first
failure. The fixture contains no raw replay or consumer source material.

Harness Contract v1 is an offline contract/evaluator slice. It does not add a
public CLI, live execution loop, host hook, controlled ablation, Dashboard
integration, consumer mutation, model or network call, Git action, release, or
deployment. The next product connection is not yet decided.
