## Verified-session handoff and rollover contract

- ADR-0012 rejects deleting `.agentgov/current-task.json`: deletion loses the
  exact session identity and would make a lone completed admitted task
  automatically discoverable again.
- The accepted future transition appends one immutable
  `session.handed_off: handed_off` event after re-establishing the exact active
  task digest, comparison base, fresh verified evidence, and in-scope snapshot.
- The event requires exact `HANDOFF` from a real terminal. Dry-run, redirected,
  cancelled, non-interactive, stale, drifted, and duplicate paths write
  nothing; a matching prior handoff is idempotent.
- Handoff means only that a human ended automatic routing responsibility for
  the working-copy session. It does not claim requirement correctness,
  architecture approval, implementation acceptance, Monitor review, commit,
  merge, release, or deployment authority.
- The pointer, task, completion evidence, Monitor output, and prior events stay
  intact. The later rollover reuses a separate
  `govern start --replace-active --dry-run` preview and exact `REPLACE`.
- Automatic discovery must exclude the same handed-off task digest, retain
  explicit choice among multiple tasks, and treat a changed digest only through
  normal reviewed start.
- Monitor remains a derived read model. Future support may display handoff
  separately from completion and print the handoff preview as guidance, but it
  cannot self-report human review.
- No runtime, schema, CLI, event, Monitor, `next`, workflow, release, update,
  consumer, or external behavior changed in this decision slice.
