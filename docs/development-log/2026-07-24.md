# Agent Governance Starter Kit Development Log — 2026-07-24

## Outcome

The first Taxi adoption supplied real onboarding evidence. Governance
inspection, dry-run, scaffold creation, and repository checks succeeded, but
the path required more assistance than the intended ten-minute experience.

## Friction observed

- Cloning the starter inside a deeply nested Windows repository caused wheel
  construction to fail with a path-related `No such file or directory`.
- Installing directly from GitHub into an active environment succeeded.
- `python -m agentgov` avoided command-discovery ambiguity.
- The initial guidance used invalid repository-check syntax before it was
  corrected to `python -m agentgov check repository .`.
- The adopting repository had a stale `.venv`, but repairing that project
  environment was not necessary to complete governance adoption.
- Users could reasonably interpret successful scaffold creation or `FAIL=0`
  as completion even though project-specific capability, evidence, artifact,
  and human-approval work remained.

## Documentation completed

- Reworked the Quickstart around the command sequence exercised in Taxi.
- Added Windows nested-path, stale-environment, and check-syntax
  troubleshooting.
- Standardized primary examples on `python -m agentgov`.
- Added accessible copy controls to command blocks in the bilingual web
  guides.
- Kept WARN and ADVISORY semantics explicit after first adoption.

## Tomorrow

Design and test an isolated AgentGov execution path that does not require:

- cloning the starter into the target repository;
- modifying or repairing the target project's virtual environment;
- installing the target project's development dependencies.

Do not choose or advertise a final installer until install, inspect, dry-run,
adopt, repository check, update, and uninstall behavior have been tested on
Windows.

- `git diff --check`: passed.

No tag, package release, or deployment was performed.
