# Agent Governance Starter Kit Development Log — 2026-07-25

## Outcome

AgentGov moved from a development-only installation path to a published
`0.1.0` GitHub Release with a verified one-command update lifecycle.

The supported user command is:

```powershell
agentgov update .
```

It discovers the latest stable release, downloads the wheel to a temporary
location, verifies its SHA-256, upgrades the pipx-managed installation,
launches the new executable, and continues the bounded repository refresh.

## Product work completed

- Added `doctor`, `onboard`, and `next` to reduce first-time adoption
  dependence on expert guidance.
- Added read-only update inspection and repository-only refresh contracts.
- Added the primary `agentgov update .` orchestration command.
- Added explicit `SUCCESS`, `CANCELLED`, `BLOCKED`, `INTERRUPTED`, `PARTIAL`,
  and `ERROR` outcomes with recovery commands where automation can determine
  one safely.
- Added stable-release network discovery and bounded HTTPS downloads.
- Extended the release manifest with the wheel filename, fixed-tag asset URL,
  pipx installation method, and lowercase SHA-256 digest.
- Added digest verification before installation and removal of a mismatched
  temporary artifact.
- Added pipx upgrade, installed-version verification, and new-process relaunch
  before repository refresh.
- Preserved the prior command on installation failure where pip can roll back,
  and explicitly probes whether the previous AgentGov executable remains
  usable.
- Kept update confirmation human-controlled; redirected input, JSON output,
  and non-interactive execution do not authorize writes.

## Incident and correction

The first tag-triggered release run failed during tests because the release
runner did not set `PYTHONPATH=src`. No GitHub Release or assets had been
created.

The workflow was corrected, covered by a workflow contract test, and the
unpublished tag was rebuilt on commit `3758268`. The second release run
completed successfully.
