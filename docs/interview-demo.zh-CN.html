退款任务引导示例

Coding Agent 改多了。接下来会发生什么？

一个小的退款修复通过了测试，但 Agent 还改了一条没有人要求它动的规则。

3–4 分钟 六个步骤 · 一个可观察场景 · 可选技术深挖
人的请求 修复退款金额计算错误。
本任务允许 refunds/calculation.py
需要单独决定 refunds/approval_policy.py

  1. 边界
  2. 额外改动

01

人先定下边界。

修复退款计算。如果要改审批规则，那应该是另一个决定。

已允许
人

AgentGov

Demo 脚本

回放同一场景，让这个过程可以重复展示。

02

Agent 修好了 bug——也多改了一处。

退款计算修好了。但 Agent 还把人工审批上限从 100 提高到了 500。

模拟 Agent
refunds/calculation.py范围内
- return subtotal
+ return subtotal - eligible_refund

# 请求中的计算修复
refunds/approval_policy.py范围外
- HUMAN_APPROVAL_LIMIT = 100
+ HUMAN_APPROVAL_LIMIT = 500

# 没有人要求这个改动
03

AgentGov 发现了额外改动。

一个改动文件属于本任务，另一个不属于。

BLOCKED
PASS · 允许的文件

refunds/calculation.py 符合任务范围。

FAIL · 额外文件

refunds/approval_policy.py 没有获得本任务的批准。

完成状态：BLOCKED

现有改动不会自动消失；只是这个任务现在还不能算完成。

04

接下来怎么办，仍然由人决定。

现在有一个真实决定：扩大任务，或者删掉额外改动。

人的决定
扩大任务

把审批规则改动当成一件单独的工作来评估。

删掉额外改动

已选择。审批规则不属于这个任务。

05

超出范围的改动被撤回。

为了让场景可重复，Demo 脚本把 approval_policy.py 恢复到原来的值。

DEMO 脚本
保留请求中的修复退款计算改动留下来。
恢复审批规则上限从 500 回到 100。
重新检查检查当前文件，而不是沿用上一次结果。
06

可以复核——还没有接受。

额外改动已经删除。请求中的修复和它的测试现在通过当前检查。
