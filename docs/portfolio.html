AgentGov's adoption and PR machinery was useful and tested, yet accumulated into a product-center drift.

Contract boundaryScope

A deterministic boundary should not pretend to understand intent.

AgentGov can decide whether changed paths are inside declared scope without declaring that the code is relevant or correct.

The checker uses exact repository-relative path segments across staged, unstaged, renamed, deleted, copied, and non-ignored untracked changes. Architecture relevance is emitted separately as an advisory review question.

Path inside admitted prefix → deterministic fact Change advances requirement → advisory judgment Scope exception → explicit human decision
Evidence tierSchema-defined + fixture-tested + Git-observed

Boundary: an in-scope path is not proof of semantic relevance, architectural correctness, or implementation quality.

Completion contractEvidence

A successful command is evidence, not completion authority.

Fresh results become stale when the bound change snapshot changes, and no self-reported claim is silently upgraded to verified.

Evidence binds the task digest, comparison base, committed changes, staged and unstaged state, renames, and non-ignored untracked identities. The record stores hashes and outcomes rather than source content or credential-like values.

Declared commands pass + snapshot unchanged → verified evidence Verified evidence ≠ sufficient tests Verified evidence ≠ merge, release, or deployment approval
Evidence tierSnapshot-bound validation + reconciliation contract

Boundary: verified means the declared commands passed for the recorded change set. Requirement satisfaction remains a human judgment.

Evidence boundary

What this portfolio supports—and what it deliberately does not claim.

AgentGov exposes repository evidence and preserves uncertainty. It is a governance starter and development control layer, not a certificate, hidden AI judge, or autonomous authority. This page does not authorize commit, merge, publish, release, or deployment.

Supported here

  • A repository-native governance lifecycle is documented and implemented in development source.
  • Selected deterministic contracts have schemas, fixtures, tests, and inspectable reports.
  • Advisory findings and denied authority are represented explicitly.
  • AI Radar lineage and extraction exclusions are recorded.

Not claimed

  • That static checks prove semantic correctness, architecture quality, or requirement value.
  • That an approval record proves reviewer comprehension.
  • That repository protocols mechanically control every coding-agent runtime.
  • That any report authorizes commit, merge, publish, release, or deployment.
