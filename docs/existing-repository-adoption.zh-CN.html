已有项目 · 安全接入

在不覆盖仓库的情况下接入治理。

先进行只读检查，再预览每次计划写入，保留现有文件，并明确解决指令权威关系。

安全契约

inspect 永不写入；adopt --dry-run 展示计划；adopt 只创建缺失的起始文件，并拒绝路径冲突。这些命令都不会运行 Git，也不会授权合并、发布或部署。

1. 检查仓库中已有的内容

PowerShell
agentgov inspect C:\work\customer-api
Bash / zsh
agentgov inspect ~/work/customer-api
PRESENT保留并审阅现有治理路径。
MISSING接入计划可以创建该路径。
DISCOVERED发现其他指令文件，需要人工决定权威关系。
CONFLICT必须先解决文件类型或符号链接冲突。

示例：仓库已经存在 CLAUDE.md

CLI 会发现该文件，但不会自动把它合并进 AGENTS.md。维护者必须决定它是从属、互补还是冲突关系。

DISCOVERED instructions: CLAUDE.md
MISSING    governance: AGENTS.md
NEXT       接入前决定指令权威关系

这里不会自动重写，因为指令优先级属于项目决策。

2. 先预览，再创建

agentgov adopt path/to/repository --project-name "Customer API" --dry-run
agentgov adopt path/to/repository --project-name "Customer API"

移除 --dry-run 前，审阅每一条 CREATE 和 PRESERVE。如果计划出现 CONFLICT，应停止并修正路径，不要强制写入。

3. 让脚手架反映真实情况

  1. 替换占位符，或记录负责人和明确延期。
  2. 在 AGENTS.md 中说明指令优先级。
  3. 声明真实的能力负责人、风险、调用方和人工审阅阶段。
  4. 只添加真实存在的证据；缺少证据时保持 needs_seed_cases。
  5. 运行 agentgov check repository，审阅每个 WARN、FAIL 和 ADVISORY。

验证结果示例

PASS required:constitution — AGENTS.md 已存在
WARN governance:placeholders — 仍有未解决的占位符
ADVISORY governance:human-review — 确认审批边界

PASS 只确认确定性事实；WARN 需要完成或明确延期；ADVISORY 需要责任人作出决定。
