Existing project · safe adoption

Adopt governance without overwriting the repository.

Start read-only, preview every planned write, preserve existing files, and explicitly resolve instruction authority.

The safety contract

inspect never writes. adopt --dry-run shows the plan. adopt creates only missing starter files and refuses path conflicts. None of these commands runs Git or authorizes merge, release, or deployment.

1. Inspect what already exists

PowerShell
agentgov inspect C:\work\customer-api
Bash / zsh
agentgov inspect ~/work/customer-api
PRESENTPreserve and review the existing governance path.
MISSINGThe adoption plan may create this path.
DISCOVEREDAnother instruction file exists and needs a human authority decision.
CONFLICTA file type or symbolic-link conflict must be resolved first.

governance/artifacts is optional generated output, not a core adoption path. Its absence does not leave inspect or doctor unresolved.

Example: a repository already has CLAUDE.md

The CLI discovers the file but does not merge it into AGENTS.md. A maintainer must decide whether it is subordinate, complementary, or conflicting.

DISCOVERED instructions: CLAUDE.md
MISSING    governance: AGENTS.md
NEXT       decide instruction authority before adoption

This is intentionally not an automatic rewrite: instruction precedence is a project decision.

2. Preview, then create

agentgov adopt path/to/repository --project-name "Customer API" --dry-run
agentgov adopt path/to/repository --project-name "Customer API"

Review every CREATE and PRESERVE line before removing --dry-run. If the plan contains CONFLICT, stop and correct the path instead of forcing a write.

3. Make the scaffold truthful

  1. Replace placeholders or record an owner and explicit deferral.
  2. Document instruction precedence in AGENTS.md.
  3. Declare real capability owners, risks, callers, and human-review stages.
  4. Add evidence that actually exists; keep missing evidence as needs_seed_cases.
  5. Run agentgov check repository and review every WARN, FAIL, and ADVISORY.

Example validation result

PASS required:constitution — AGENTS.md exists
WARN governance:placeholders — unresolved placeholders remain
ADVISORY governance:human-review — confirm approval boundaries

PASS confirms a deterministic fact only. WARN requires completion or explicit deferral. ADVISORY requires an accountable human decision.
