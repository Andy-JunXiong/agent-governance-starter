10 分钟接入路径

快速入门

先检查，再预览每次写入，只创建缺失的治理文件，最后审阅自动化无法决定的事项。

一条命令完成更新

agentgov update .
# 只读检查：
agentgov update --check .

主命令会发现最新稳定 GitHub Release、报告版本和仓库兼容性、只请求一次准确的 UPDATE 确认、校验 wheel 的 SHA-256、更新 pipx、启动新版工具、应用有边界的仓库变化并自动复检。只读命令永不写入。

进度按 CHECK、PLAN、APPLY 和 VALIDATE 展示。最终状态明确区分 SUCCESS、CANCELLED、BLOCKED、INTERRUPTED、PARTIAL 和 ERROR。如果中断或验证失败前已经创建文件，CLI 会列出该文件并提供一条 RECOVERY 恢复命令。

开始之前

在需要治理的仓库根目录打开终端，使用 Python 3.11 或更新版本，并确认 pipx 可用。静态检查通过只表示声明的确定性契约成功执行；它不授权合并、发布或部署。

1. 安装

请从需要治理的仓库运行以下命令。它们会把已发布的稳定版 0.2.1 安装到隔离的 pipx 环境，而不会把 starter 源码复制进被治理仓库。

python --version
pipx install "https://github.com/Andy-JunXiong/agent-governance-starter/releases/download/v0.2.1/agent_governance_starter-0.2.1-py3-none-any.whl"
agentgov --version
agentgov --help

不安装直接运行

如果要开发 starter kit，请把它克隆到独立且较短的路径，再从包含 src 目录的 clone 根目录运行以下其中一种命令。不要把 starter clone 到被治理仓库内部。

PowerShell
$env:PYTHONPATH = "src"
python -m agentgov --help
Bash / zsh
PYTHONPATH=src python -m agentgov --help

2. 接入已有仓库

如果终端已经位于目标仓库根目录，请使用 .。每次只运行一条命令，确认输出后再继续。

agentgov inspect .
agentgov adopt . --project-name "My Project" --dry-run
agentgov adopt . --project-name "My Project"
agentgov check repository .
PRESENT保留并审阅现有治理路径。
MISSING决定接入计划是否应创建它。
DISCOVERED人工审阅其他工具的仓库指令。
CONFLICT先解决路径类型或符号链接冲突。

CLI 不覆盖普通文件，不合并 CLAUDE.md 或厂商指令，也不运行 Git 命令。

首次检查的正常结果：刚接入的仓库可能同时出现 PASS、WARN 和 ADVISORY。占位符、draft seed cases、尚未配置的 artifacts 和人工审批边界仍需按项目实际情况审阅。FAIL=0 不代表接入已经完成。

3. 创建新仓库

PowerShell
$Project = Join-Path $PWD "governed-project"
agentgov init $Project --project-name "My Project"
agentgov check repository $Project
Bash / zsh
PROJECT="$PWD/governed-project"
agentgov init "$PROJECT" --project-name "My Project"
agentgov check repository "$PROJECT"

4. 检查并生成报告

PowerShell
agentgov check repository path/to/project
agentgov report repository path/to/project `
  --format html `
  --output path/to/project/governance-report.html
Bash / zsh
agentgov check repository path/to/project
agentgov report repository path/to/project \
  --format html \
  --output path/to/project/governance-report.html

5. 仍需完成的人工工作

  1. 替换占位符，或明确记录延期。
  2. 解决各指令文件之间的权威关系。
  3. 声明真实的能力归属、风险和人工审阅阶段。
  4. 添加经过审阅的评估证据。
  5. 为 ADVISORY 发现记录可追责的决定。

继续阅读

已有仓库接入指南 安全检查、预演并接入现有项目。 生成文件填写指南 理解并填写各项治理文件。 故障排查 处理安装、冲突、WARN 和 ADVISORY。 查看示例报告 了解检查结果和人工审阅边界。

引导式接入开发预览

当前开发版本还提供按仓库状态引导的流程。它已通过隔离的 Windows 自动化演练，但尚未完成一次全新的无现场指导真人试用，因此暂不替换下面的主流程。

agentgov doctor .
agentgov onboard . --project-name "My Project" --dry-run
agentgov onboard . --project-name "My Project"
agentgov next .

doctor 和 next 始终只读。交互式 onboard 仅接受真实终端中精确输入的 ADOPT，随后自动运行首次仓库检查；重定向输入和非交互模式都不能授予写权限。

已接受的自动化产品方向

当前手动开发命令链只是开发和故障恢复接口，不是普通用户的目标流程。下一阶段产品允许用户直接向 Coding Agent 提出任务，由 AgentGov 自动协调上下文、范围、预批准验证、fresh evidence、Monitor 和 Dashboard，只在真正的语义或权限边界打断用户。

这个自动体验以及 Live Sessions、Protection Events、Benefit 和 Learning 视图尚未包含在 stable 0.2.1，也不是 v0.3.0rc1 的主要界面。详见已批准的产品需求。

开发源自动化状态

开发源现已实现单次前景 agentgov dev 协调循环和最小参考 Adapter，可自动执行范围观察、已批准验证、完成对账、人工评审后的 handoff 与 Dashboard 刷新。Codex、Claude Code 或 IDE 的实时事件接入、自然语言任务准入和可视化卡片仍是下一阶段；stable 0.2.1 与 v0.3.0rc1 未改变。
