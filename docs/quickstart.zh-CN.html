版本边界：稳定版 0.2.1 可安装；公开预发行版 0.3.0rc1 与开发源继续扩展 Coding Agent 旅程。

10 分钟接入路径

快速入门

先检查，再预览每次写入，只创建缺失的治理文件，最后审阅自动化无法决定的事项。

开始之前

在仓库根目录打开终端，使用 Python 3.11 或更新版本，并确认 pipx 可用。检查通过只表示声明的确定性契约成功执行；它不授权合并、发布、release 或部署。

选择你的目标

在已有仓库接入 AgentGovinspect → adopt --dry-run → adopt → check 创建新的治理仓库init → check 生成治理报告check → report 查看开发功能跳过稳定路径，直接查看独立的成熟度与证据链接。

1. 安装稳定版 0.2.1

安装已发布的稳定包，而不把 starter 源码复制进被治理仓库。

python --version
pipx install "https://github.com/Andy-JunXiong/agent-governance-starter/releases/download/v0.2.1/agent_governance_starter-0.2.1-py3-none-any.whl"
agentgov --version
agentgov --help

只有开发 starter 时才从源码运行

把 starter 克隆到独立的短路径，不要把 starter clone 到被治理仓库，再从 clone 根目录运行：

PowerShell
$env:PYTHONPATH = "src"
python -m agentgov --help
Bash / zsh
PYTHONPATH=src python -m agentgov --help

2. 接入已有仓库

每次只运行一条命令：先检查，再预览所有计划文件，最后只创建缺失项。

agentgov inspect .
agentgov adopt . --project-name "My Project" --dry-run
agentgov adopt . --project-name "My Project"
agentgov check repository .

稳定版 0.2.1 针对空仓库预览的真实选取行：

PLAN governance/contract.json
PLAN AGENTS.md
SUMMARY CREATE=26 PRESERVE=0
NOTE adopt dry-run: no repository files were created or modified
NOTE adopt: adoption does not authorize merge, publish, release, or deploy
PRESENT保留现有治理路径。
MISSING审阅计划建议创建的内容。
DISCOVERED人工审阅其他工具的仓库指令。
CONFLICT先解决路径类型或符号链接冲突。

CLI 不覆盖普通文件、不合并厂商指令，也不运行 Git。首次检查可能同时出现 PASS、WARN 和 ADVISORY；FAIL=0 不表示接入或人工审阅已经完成。

3. 创建新仓库

PowerShell
$Project = Join-Path $PWD "governed-project"
agentgov init $Project --project-name "My Project"
agentgov check repository $Project
Bash / zsh
PROJECT="$PWD/governed-project"
agentgov init "$PROJECT" --project-name "My Project"
agentgov check repository "$PROJECT"

4. 检查并生成报告

PowerShell
agentgov check repository path/to/project
agentgov report repository path/to/project `
  --format html `
  --output path/to/project/governance-report.html
Bash / zsh
agentgov check repository path/to/project
agentgov report repository path/to/project \
  --format html \
  --output path/to/project/governance-report.html

打开报告即可看到确定性事实、不完整证据和仍需人类决定的事项。生成报告不授权合并、发布、release 或部署。

5. 完成人工工作

  1. 替换占位符，或明确记录延期。
  2. 解决各指令文件之间的权威关系。
  3. 声明真实的能力归属、风险和人工审阅阶段。
  4. 添加经过审阅的评估证据。
  5. 为 ADVISORY 发现记录可追责的决定。

继续稳定路径

已有仓库接入指南 安全检查、预演并接入现有项目。 生成文件填写指南 理解并填写各项治理文件。 故障排查 处理安装、冲突、WARN 和 ADVISORY。 查看示例报告 了解检查结果和人工审阅边界。

维护已接入仓库

agentgov update --check .
# 审阅计划后：
agentgov update .

检查命令只读。更新仍需要真实终端中的精确确认，会验证稳定 release，只应用有边界的计划并重新运行检查。

开发预览

稳定版 0.2.1 仍是受支持的安装和接入路径。公开的 0.3.0rc1 是独立、不可变的预发行快照。开发源继续加入 Coding Agent 生命周期、Adapter、drift review 和 replay 安全能力，并有独立证据边界。本地已安装或已预检模块不等于稳定发布或消费者已启用能力；新的无指导主要产品真人试用仍未证明。

自动化产品方向查看已接受目标和尚未实现的部分。 成熟度与证据边界区分稳定、预发行、开发源、已安装和未证明状态。 Adapter 详情检查精确开发契约和宿主限制。 Replay 安全证据检查 reservation、claim、recovery 和非授权边界。

另见 drift review 提醒和证据讲解。这些开发记录都不授权 Git、合并、发布、release、replay 或部署。
