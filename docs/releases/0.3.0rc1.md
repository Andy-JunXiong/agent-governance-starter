# AgentGov 0.3.0rc1 release candidate

Status: prepared for GitHub Pre-release; not promoted to stable or adopted by a
consumer repository.

## Purpose

This candidate makes development-time governance the primary AgentGov product
loop. It packages human-admitted task contracts, architecture-aware context,
working-copy scope checks, fresh completion evidence, guided routing, redacted
event transfer, a static Development Monitor, and an explicit verified-session
handoff. It does not authorize autonomous commit, merge, publication, release,
consumer migration, or deployment.

## Added

- Compact and standard development-task contract 1.1 with deterministic
  structure/reference checks and explicit advisory objective review.
- Artifact-owned task context selection with source hashes, selection reasons,
  capability links, and denied mutation authority.
- Git-aware changed-file scope checks covering committed, staged, unstaged,
  renamed, deleted, and non-ignored untracked paths.
- Guided `govern start`, `govern check`, and `govern finish` sessions with
  immutable local events, declared-command validation, fresh evidence, and
  `verified` versus `needs_evidence` reconciliation.
- Metadata-only `export development` bundles and the static Development Monitor
  with explicit local, exported, CI-only, and combined source labels.
- Read-only `agentgov next` lifecycle routing plus exact-confirmation
  `govern handoff`, which preserves the task pointer and prior evidence while
  separating verified completion from routing handoff.
- A default-off future-0.3 managed-workflow path for publishing only the
  derived Development Monitor HTML artifact.

## Compatibility

- Supported source tool versions: 0.1.0, 0.2.0, and 0.2.1.
- Readable and target repository layout: 1.0.
- Repository migrations: none.
- Existing stable 0.1 and 0.2 managed workflow bytes remain unchanged.
- The stable update planner intentionally rejects release-candidate manifests;
  this candidate cannot become an automatic consumer update.

## Evidence and limits

- The complete source suite and release gates must pass again on the tagged
  commit before GitHub creates the Pre-release.
- Exact-wheel rehearsals use fresh environments and independent disposable Git
  repositories. They are deterministic integration evidence, not uncoached
  human usability evidence or proof of general effectiveness.
- Historical delivered task contracts are paused only to remove them from
  automatic task discovery. Paused does not mean semantically accepted,
  merged, released, or deployed.
- The wheel filename, SHA-256, installed import path, manifest validation, and
  rehearsal outcomes are recorded during the final local RC gate run.

## Gates before stable 0.3.0

- Publish and observe this reviewed GitHub Pre-release.
- Review candidate evidence and known limits separately from automated checks.
- Decide and rehearse the NYC consumer migration from a digest-verified stable
  manifest; do not migrate from this candidate channel.
- Approve the final-version source change, commit, stable tag, push, and GitHub
  Release as separate human-controlled actions.
