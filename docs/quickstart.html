10-minute adoption path

Quickstart

Inspect first, preview every write, create only missing governance files, then review what automation cannot decide.

Before you start

Open a terminal at the root of the repository you want to govern. Use Python 3.11 or newer and ensure pipx is available. A passing static check means a declared deterministic contract ran successfully; it does not authorize merge, release or deployment.

1. Install

Run these commands from the repository you want to govern. They install the published stable 0.2.1 package without copying the starter source tree into your repository.

python --version
pipx install "https://github.com/Andy-JunXiong/agent-governance-starter/releases/download/v0.2.1/agent_governance_starter-0.2.1-py3-none-any.whl"
agentgov --version
agentgov --help

Running agentgov without arguments is also a safe, read-only orientation surface. It points first-time users to doctor, next, and status without inspecting or modifying the repository.

Run without installing

For starter-kit development, clone it into a separate, short path. Then run one of these alternatives from that clone's root, where the src directory exists. Do not clone the starter inside the repository being governed.

PowerShell
$env:PYTHONPATH = "src"
python -m agentgov --help
Bash / zsh
PYTHONPATH=src python -m agentgov --help

Guided onboarding development preview

After installation, the current development build also provides a state-dependent path. It has passed an isolated automated Windows rehearsal, but it has not yet completed a fresh uncoached human pilot and therefore does not replace the primary steps that follow.

agentgov doctor .
agentgov onboard . --project-name "My Project" --dry-run
agentgov onboard . --project-name "My Project"
agentgov next .

doctor and next are read-only. Interactive onboard writes only after exact ADOPT from a real terminal, runs the first repository check, and never treats redirected or non-interactive input as write authority.

Accepted automatic product direction

The manual development command sequence is a development and fallback interface, not the intended ordinary-user journey. The approved next product lets a user request work through a coding agent while AgentGov automatically coordinates context, scope, pre-approved validation, fresh evidence, Monitor and Dashboard updates, and interrupts only at real semantic or authority boundaries.

This automatic experience and its Live Sessions, Protection Events, Benefit and Learning views are not implemented in stable 0.2.1 or as the primary v0.3.0rc1 UI. See the approved product requirements.

One-command update

agentgov update .
# Read-only alternative:
agentgov update --check .

The primary command discovers the latest stable GitHub Release, reports versions and repository compatibility, requests one exact UPDATE confirmation, verifies the wheel SHA-256, updates pipx, relaunches the new tool, applies the bounded repository change, and reruns validation. The check alternative never writes.

Progress is labeled CHECK, PLAN, APPLY, and VALIDATE. Final states distinguish SUCCESS, CANCELLED, BLOCKED, INTERRUPTED, PARTIAL, and ERROR. If a file was created before interruption or failed validation, the CLI lists it and prints one RECOVERY command.

2. Adopt an existing repository

If your terminal is already at the target repository root, use .. Run one command at a time and review its output before continuing.

agentgov inspect .
agentgov adopt . --project-name "My Project" --dry-run
agentgov adopt . --project-name "My Project"
agentgov check repository .
PRESENTPreserve and review the existing governance path.
MISSINGDecide whether the adoption plan should create it.
DISCOVEREDReview another tool's repository instructions manually.
CONFLICTResolve the path type or symbolic-link conflict first.

The CLI does not overwrite regular files, merge CLAUDE.md or vendor instructions, or run Git commands.

Expected first check: a newly adopted repository can report PASS with WARN and ADVISORY findings. Placeholders, draft seed cases, missing artifacts and human approval boundaries still require project-specific review. FAIL=0 does not mean adoption is complete.

3. Start a new repository

PowerShell
$Project = Join-Path $PWD "governed-project"
agentgov init $Project --project-name "My Project"
agentgov check repository $Project
Bash / zsh
PROJECT="$PWD/governed-project"
agentgov init "$PROJECT" --project-name "My Project"
agentgov check repository "$PROJECT"

4. Check and generate a report

PowerShell
agentgov check repository path/to/project
agentgov report repository path/to/project `
  --format html `
  --output path/to/project/governance-report.html
Bash / zsh
agentgov check repository path/to/project
agentgov report repository path/to/project \
  --format html \
  --output path/to/project/governance-report.html

5. Human work still required

  1. Replace or explicitly defer placeholders.
  2. Resolve authority relationships among instruction files.
  3. Declare real capability ownership, risk and human-review stages.
  4. Add reviewed evaluation evidence.
  5. Record accountable decisions for ADVISORY findings.
