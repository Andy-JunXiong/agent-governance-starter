10-minute adoption path

Quickstart

Inspect first, preview every write, create only missing governance files, then review what automation cannot decide.

Before you start

Open a terminal at the repository root. Use Python 3.11 or newer and ensure pipx is available. A passing check means a declared deterministic contract ran; it does not authorize merge, publication, release, or deployment.

1. Install stable 0.2.1

Install the published stable package without copying this starter source tree into the repository you want to govern.

python --version
pipx install "https://github.com/Andy-JunXiong/agent-governance-starter/releases/download/v0.2.1/agent_governance_starter-0.2.1-py3-none-any.whl"
agentgov --version
agentgov --help

Run from source only when developing the starter

Clone the starter into a separate short path. Do not clone the starter inside the governed repository. Then run from the clone root:

PowerShell
$env:PYTHONPATH = "src"
python -m agentgov --help
Bash / zsh
PYTHONPATH=src python -m agentgov --help

2. Adopt an existing repository

Run one command at a time. Inspect first, preview every planned file, then create only what is missing.

agentgov inspect .
agentgov adopt . --project-name "My Project" --dry-run
agentgov adopt . --project-name "My Project"
agentgov check repository .

Selected real lines from a stable 0.2.1 empty-repository preview:

PLAN governance/contract.json
PLAN AGENTS.md
SUMMARY CREATE=26 PRESERVE=0
NOTE adopt dry-run: no repository files were created or modified
NOTE adopt: adoption does not authorize merge, publish, release, or deploy
PRESENTPreserve the existing governance path.
MISSINGReview what the plan proposes to create.
DISCOVEREDReview another tool's instructions manually.
CONFLICTResolve the path or symbolic-link conflict first.

The CLI does not overwrite regular files, merge vendor instructions, or run Git. A first check may contain PASS, WARN, and ADVISORY findings; FAIL=0 does not mean adoption or human review is complete.

3. Start a new governed repository

PowerShell
$Project = Join-Path $PWD "governed-project"
agentgov init $Project --project-name "My Project"
agentgov check repository $Project
Bash / zsh
PROJECT="$PWD/governed-project"
agentgov init "$PROJECT" --project-name "My Project"
agentgov check repository "$PROJECT"

4. Check and generate a report

PowerShell
agentgov check repository path/to/project
agentgov report repository path/to/project `
  --format html `
  --output path/to/project/governance-report.html
Bash / zsh
agentgov check repository path/to/project
agentgov report repository path/to/project \
  --format html \
  --output path/to/project/governance-report.html

Open the report to see deterministic facts, incomplete evidence, and decisions that still require a person. Report generation does not authorize merge, publication, release, or deployment.

5. Complete the human work

  1. Replace or explicitly defer placeholders.
  2. Resolve authority relationships among instruction files.
  3. Declare real capability ownership, risk, and human-review stages.
  4. Add reviewed evaluation evidence.
  5. Record accountable decisions for ADVISORY findings.

Maintain an adopted repository

agentgov update --check .
# After reviewing the plan:
agentgov update .

The check is read-only. The update command still requires exact interactive confirmation, verifies the stable release, applies only its bounded plan, and reruns validation.

Development preview

Stable 0.2.1 remains the supported installation and adoption path. Published 0.3.0rc1 is a separate immutable prerelease snapshot. Development source adds coding-agent lifecycle, Adapter, drift-review, and replay-safety work with separate evidence boundaries. Locally installed or preflighted modules are not stable releases or consumer-active behavior, and a fresh uncoached primary-product pilot remains unproven.

Automatic product directionRead the accepted outcome and what remains unimplemented. Maturity and evidence boundarySeparate stable, prerelease, development, installed, and unproven claims. Adapter detailsInspect the exact development contract and host limits. Replay-safety evidenceInspect reservation, claim, recovery, and non-authority boundaries.

See also drift-review reminders and the guided evidence walkthrough. None of these development records authorizes Git, merge, publication, release, replay, or deployment.
