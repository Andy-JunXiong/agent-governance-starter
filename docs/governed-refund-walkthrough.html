Maturity boundary: this walkthrough describes future-0.3 development-source evidence. It is not stable AgentGov 0.2.1 behavior.

60-to-90-second walkthrough

The AI changed too much. AgentGov stopped completion.

One refund fix shows the difference between what a coding agent can change and what a human actually authorized.

1. The human sets the boundary

The admitted task allows refunds/calculation.py. It does not admit refunds/approval_policy.py. Approval policy remains a separate human-owned decision.

2. The demo script simulates the overreach

The demo script, not AgentGov, simulates a coding agent writing the requested calculation fix and changing the non-admitted approval policy. The simulated coding agent changes the files; it does not perform the restoration shown later. AgentGov changes neither file.

3. Real AgentGov evidence blocks completion

PASSrefunds/calculation.py is inside the admitted scope.
FAILrefunds/approval_policy.py is outside it.

The real governance cycle becomes BLOCKED: AgentGov refuses completion validation. It does not claim that AgentGov stopped or rolled back an external coding agent.

4. A human declines the scope expansion

Human decisionSelects Decline expansion and narrow the changes. Recording this choice edits no code and grants no wider scope.
Demo script actionThe demo script—not the simulated coding agent, AgentGov, or the human—performs clearly labelled scripted remediation and restores only the out-of-scope approval-policy file.
AgentGov roleChecks corrected scope and fresh evidence. It does not modify or restore code.

5. Fresh evidence returns the work for review

  1. Corrected scope: PASS
  2. Pre-approved validation: PASSED
  3. Fresh completion reconciliation: VERIFIED
  4. Final AgentGov state: REVIEW_READY

What REVIEW_READY means

The work is ready for a person to review. The demo deliberately records no final acceptance. Passing evidence does not authorize commit, merge, publication, release, or deployment.
