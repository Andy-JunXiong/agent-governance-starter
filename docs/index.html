A prompt can change production behavior without making ownership, evidence or approval boundaries visible to the reviewer.

The core principle

No governance score. On purpose.

A single percentage would hide whether a repository has a broken contract, incomplete evidence or an unresolved human decision. Agent Governance reports each state separately and refuses precision it cannot justify.

PASS · FACT SATISFIED

A deterministic contract passed. This is not approval.

WARN · HONESTLY INCOMPLETE

Configuration or evidence still needs work or an owner.

FAIL · CONTRACT VIOLATED

A deterministic requirement is broken and must be fixed.

ADVISORY · HUMAN JUDGMENT

Static analysis cannot decide. An accountable person must.

Concrete example

An AI drafts customer refund replies.

The task affects money and customer expectations. A prompt alone cannot show who owns it, what was tested or whether an older review is still current.

Before governance

  • Prompt hidden inside application code
  • No named owner or risk level
  • No reviewed case for an unapproved refund
  • Prompt changes silently invalidate old review

With Agent Governance

  • Capability manifest connects purpose, owner and source
  • High risk requires an explicit human-review stage
  • Evaluation records expected and prohibited behavior
  • Source hashes detect changes after review
What gets added

Small files make the invisible contract reviewable.

Each repository artifact answers one practical question. None is treated as proof on its own.

AGENTS.md

Operating rules

What an agent may change, must verify and must escalate.

capability.json

Capability identity

Purpose, owner, risk, contracts and provenance.

evaluation/

Evidence state

Reviewed cases, known failures and honest readiness.

SKILL.md

Working protocol

Triggers, workflow, stop conditions and handoff.

artifact.json

Review snapshot

Manifest and source hashes for drift detection.
